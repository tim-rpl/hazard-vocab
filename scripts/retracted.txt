# Retracted phrases — swept on every `make lint` by scripts/sweep-retracted.py
#
# WHAT THIS GUARANTEES, AND WHAT IT DOES NOT.
#
# It makes VERBATIM reintroduction of a retracted phrase impossible. It
# says NOTHING about a paraphrase. claims.md C22 row 12 records that
# exact over-read: the sweep "keys on the sentence, not the proposition
# … a claim restated in different words is its failure mode. Three
# shipped past a green run" — all three in accepted ADRs.
#
# So do not read a green sweep as "reintroduction is impossible". Read it
# as "these exact strings are absent". The proposition remains checkable
# only by reading.
#
# FORMAT: one phrase per line. Blank lines and #-comments ignored.
# Matched with `git grep -F -f` — fixed strings, not regexes.
#
#   phrase  <TAB>  date  <TAB>  withdrawing message or commit
#
# The format is documented with the word TAB rather than a literal tab,
# deliberately: the check below fires on ANY comment line carrying a
# literal tab, and a comment illustrating the format with real tabs is a
# false positive in the check written to catch a silent failure. Mention
# versus use, in the file documenting the rule.
#
# THIS FILE MUST END WITH A NEWLINE. The workflow is `>>`, the file ends
# in comments, and an append onto a `#` line is silently skipped — the
# sweep then reports "inspected nothing" and passes. sweep-retracted.py
# asserts both the trailing newline and that no comment line carries a
# tab, which is the signature of a swallowed entry.
#
# ENTERING THE PHRASE IS PART OF RETRACTING, NOT A FOLLOW-UP. A
# retraction made without an entry here is checked once, at the moment it
# is made, and nothing catches the site the sweep would have found. That
# has happened: a trigger was retracted in a module docstring and left
# live in a function docstring of the same file, one round after this
# instrument was built to catch exactly that, because the phrase was
# never entered.
#
# CHOOSE A SUBSTRING PRESENT IN THE RETRACTED CLAIM AND ABSENT FROM THE
# RETRACTION OF IT. A retraction usually quotes what it withdraws, so the
# obvious phrase fires on the withdrawal and reads as a live
# reintroduction. Measured on the case above: `more than one file`
# appears in both the claim and both retractions of it and is useless;
# `first multi-file` appears only in the claim and is the entry.
#
# THE THIRD PROPERTY HAS ONE EXCEPTION, AND TWO ENTRIES BELOW RELY ON IT.
# If the retraction lives in an EXCLUDED path, the quoting does not
# matter and the obvious phrase is a valid entry. Both ADMS-line entries
# appear verbatim in the message that withdrew them — the protocol
# requires a withdrawal to index its sites by quoted opening phrase — and
# they pass only because `review-inbox.md` is excluded. That is the
# interaction between this rule and exclusion 1, not a defect in either
# entry, and it is the reason both survive.
#
# ENTER THE SHORTEST DISTINCTIVE SUBSTRING, not the full markup-bearing
# string. The same claim in two typographic forms is two byte sequences —
# `` `CLAUDE.md`'s ADMS line `` and CLAUDE.md's ADMS line differ — and a
# full string silently misses a reintroduction typed without the markup,
# which is the invisible direction.
#
# The date and provenance make an entry AUDITABLE rather than
# accumulating as apparent coverage: a phrase referencing a file since
# deleted can no longer fire, and only the provenance says so.
#
# EXCLUSIONS the sweep applies, and why each is not optional:
#
#   review-inbox.md, review-inbox-archive/
#       Append-only channel. Hits there are history by design —
#       .claude/rules/gate-messages.md, "Withdrawing a claim from a
#       reviewed message". A reviewed message is never marked.
#
#   docs/plan/guard-fixtures/
#       These files carry retired figures BY CONSTRUCTION; that is what
#       they are for, and several are deliberately bare because a
#       fixture carrying a retraction cue would exempt itself. Measured:
#       9 of 15 hits on the first five-phrase list were here.
#
#   scripts/retracted.txt
#       This file contains every retracted phrase and would match all of
#       them.
#
#   claims.md
#       Supersession-supporting. gate-messages.md rule 4 names it as one
#       of the documents where a withdrawn thing MUST remain findable
#       backward, since the channel is findable forward only. A register
#       that cannot quote what it retracted is not a register — the first
#       phrase entered here fired on C22 row 18, which is O's record OF
#       the retraction. Cost, stated: a genuinely live claim written into
#       claims.md is invisible here. That is O's file and a different
#       reviewer's failure.
#
# THE OVER-EXCLUDE DIRECTION IS THE DANGEROUS ONE. A sweep that forgets
# an exclusion reports history as live — noisy, self-correcting. A sweep
# that over-excludes reports LIVE TEXT AS HISTORY, silently. A live claim
# written into an excluded path is invisible to this instrument, and no
# match-direction fixture can show that. See
# scripts/sweep-fixtures/README.md.
